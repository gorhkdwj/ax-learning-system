업무 질문에서 구현까지의 층위

도메인 모델링은 업무 질문에서 시작합니다. 먼저 무엇을 답해야 하는지 정하고, 그 질문에 필요한 개념과 의미를 정의한 뒤 데이터 구조와 저장 방식을 선택합니다.

ontology는 의미 모델이고 schema는 데이터 구조 계약입니다. JSON·RDBMS·그래프는 그 모델을 구현하는 표현 방식이므로 어느 저장 기술도 자동으로 올바른 ontology를 만들지 않습니다.

  • 업무 질문 → 개념·의미 정의 → 데이터 구조 → 실제 데이터 → 조회·검증
  • 분류, 의미, 구조, 실제 데이터를 같은 것으로 취급하지 않습니다.
  • 가장 복잡한 기술이 아니라 질문을 만족하는 가장 단순한 표현을 선택합니다.
Taxonomy와 Schema

taxonomy는 개념을 상위·하위 범주로 배열하여 분류와 탐색을 돕습니다. schema는 필드명, 자료형, 필수 여부, 키와 제약처럼 데이터가 가져야 할 구조를 정의합니다.

taxonomy만으로 개별 대상의 상태와 임의 관계를 충분히 표현하기 어렵고, schema만으로 각 필드의 공유 의미와 도메인 가정을 자동으로 보장하지는 못합니다.

  • taxonomy의 중심 질문: 무엇의 하위·상위 범주인가?
  • schema의 중심 질문: 어떤 필드·형식·제약으로 저장하는가?
Ontology와 Knowledge Graph

ontology는 도메인의 개념, 속성, 관계와 필요한 제약을 명시합니다. knowledge graph는 실제 개별 대상과 그 관계를 그래프 형태로 연결한 데이터입니다.

문서·문서버전·원천의 의미와 관계 규칙은 ontology에 해당하고, 실제 문서 A·버전 3·원천 17의 연결은 knowledge graph에 해당합니다. 동일한 ontology를 RDBMS로 구현할 수도 있습니다.

  • ontology는 의미와 규칙을 정의합니다.
  • knowledge graph는 실제 대상과 연결을 표현합니다.
  • 그래프 DB 도입은 ontology의 정확성을 보장하지 않습니다.
Class·Instance·Property

class는 같은 정의를 공유하는 대상의 유형이고 instance는 그 유형에 속하는 구체적인 개별 대상입니다. 독립적인 ID와 수명주기는 class 후보를 찾는 실무 휴리스틱이지 class의 정의 자체는 아닙니다.

데이터 속성은 대상을 문자열·숫자·날짜 같은 단순 값과 연결합니다. 대상 관계는 독립적으로 식별되는 두 대상을 연결합니다. ontology에서 property는 두 종류를 함께 가리킬 수 있습니다.

  • Document는 class, annual-leave-policy는 instance입니다.
  • title은 단순 값 속성, authoredBy는 Document와 Employee 사이의 관계입니다.
  • 표시만 하는 이름은 속성일 수 있지만 별도 ID·이력·관계가 필요하면 class와 관계를 검토합니다.
State와 시간 정보

state는 대상이 특정 시점에 처한 조건이고 시간 정보는 그 상태나 관계가 언제 유효한지를 나타냅니다. active라는 상태와 effective_from이라는 시점은 분리하여 생각합니다.

현재 상태만 필요하면 필드로 충분할 수 있습니다. 상태 변경 이력 자체가 핵심 질문의 대상이면 상태 할당이나 변경 이벤트를 별도 대상으로 모델링할 수 있습니다.

  • status=active는 조건입니다.
  • effective_from=2026-08-01은 적용 시점입니다.
  • 상태와 시간 정보를 섞으면 과거 시점 질문에 답하기 어렵습니다.

핵심 질문에서 TBox 수준의 class·property·constraint와 ABox 수준의 instance를 도출하고 경계 사례를 설명합니다.

Competency Question

competency question은 완성된 모델이 답해야 할 대표 질문입니다. 도메인의 모든 명사를 모델링하는 대신 필요한 질문으로 범위와 세부 수준을 제한합니다.

각 질문에 필요한 대상, 값, 관계, 상태, 시점, 원천을 표시하고 답변 경로를 구성할 수 있어야 합니다.

  • 질문이 없으면 class와 relation이 목적 없이 늘어납니다.
  • 질문을 답하지 못하는 필드·관계 누락은 모델 실패입니다.
  • 질문과 관련 없는 개념은 현재 범위 밖으로 둘 수 있습니다.
TBox와 ABox

TBox는 어떤 종류의 대상과 관계가 가능한지 정의하는 설계도입니다. ABox는 구체적인 instance와 그에 관한 사실을 기록합니다.

DocumentVersion이라는 class와 derivedFrom이라는 relation 정의는 TBox이고, version-3 derivedFrom source-17이라는 사실은 ABox입니다.

  • TBox: class, property, domain, range, cardinality와 제약
  • ABox: 개별 instance의 class 소속, 속성값과 관계 사실
Domain·Range·Cardinality

domain은 property가 출발하는 대상 유형이고 range는 도착하는 값 또는 대상 유형입니다. cardinality는 허용되는 값이나 관계의 개수를 제한합니다.

제약은 실제 업무 규칙을 반영할 때만 추가합니다. 근거 없이 강한 제약을 만들면 정상 데이터를 거부하고, 너무 약하면 잘못된 상태를 허용합니다.

  • derivedFrom의 domain은 DocumentVersion, range는 Source일 수 있습니다.
  • 문서당 현재 버전 하나라는 규칙은 단순 class 계층이 아니라 상태·시간·고유성 제약과 연결됩니다.

RAG와 구조화 관계 검색의 경계

검색 실패와 생성 실패를 구분하고 벡터·메타데이터·관계 질의의 선택 조건을 설명합니다.

120분 예상 시간
120:00
일반 RAG

RAG는 외부 지식을 검색하여 생성 모델 입력에 제공하는 구조입니다. 검색된 문서가 틀리거나 누락되는 실패와 제공된 근거를 생성 모델이 잘못 사용하는 실패를 분리해야 합니다.

유사도는 관련성을 추정하지만 현재 유효함, 권한 허용, 버전 우선순위 같은 필수 제약을 자동으로 보장하지 않습니다.

  • ACL과 유효기간은 검색 전후의 결정적 Gate로 검사합니다.
  • source ID와 검색 trace를 보존합니다.
  • 근거가 부족하면 답변 보류를 허용합니다.
구조화 관계 질의의 도입 Gate

그래프나 ontology 기반 관계 질의는 RAG의 필수 요소가 아닙니다. 기존 방식이 해결하지 못한 필수 관계 질문을 재현 가능하게 해결할 때만 후보가 됩니다.

가변 깊이 관계가 있더라도 재귀 SQL과 관계형 모델로 충분할 수 있습니다. 그래프 방식은 ACL·최신성·추적성·운영비까지 함께 비교합니다.

  • 기존 기준선의 필수 질문 실패가 재현되어야 합니다.
  • 새 방식이 같은 질문을 해결해야 합니다.
  • 안전 Gate와 총 유지비를 통과해야 합니다.

독립 전이의 의미

장비 정비와 교육 자격 과제를 각각 수행하여 우연한 템플릿 적합이 아닌 전이 가능한 판단 기준을 확인합니다.

구조검사와 의미검사의 차이

구조검사는 ID 존재, 필수 필드와 형식 같은 결정적 조건을 빠르게 찾습니다. 그러나 이름이 존재한다는 사실만으로 실제 질문을 논리적으로 답한다는 점을 증명하지는 못합니다.

사람 의미 검토는 질문 정합성, 분류, 시간·원천, 표현 선택, 독립 전이와 사용자의 설명을 구체적인 증거로 확인합니다.

  • 두 전이 모델 파일이 실제로 존재해야 합니다.
  • 여섯 의미 기준을 모두 근거와 함께 통과해야 합니다.
  • 반복 오류가 있을 때만 최대 120분을 보충합니다.

검색 표현 선택 Probe

동일한 골든 질문에서 세 검색 snapshot을 비교하여 가장 단순한 충분 방식을 선택하고 재검토 조건을 기록합니다.

120분 예상 시간
120:00
비교 Probe

Probe는 기술 우위를 증명하도록 설계하지 않습니다. 같은 질문·문서·평가기준에서 필수 사실, 잘못된 근거, 최신성, ACL, 추적성과 유지비를 비교합니다.

모든 필수 Gate를 통과하는 방식 중 유지비가 가장 낮은 방식을 기준선으로 선택합니다. 선택하지 않은 방식의 제외 이유와 재검토 조건도 남깁니다.

  • 자동 점수와 사람 표본 검토를 함께 사용합니다.
  • 그래프는 고유 필수 관계 질문을 해결할 때만 선택 후보입니다.
  • Set의 일반 경로에서는 선택 단계지만 현재 배정 경로에서는 완료 산출물입니다.
