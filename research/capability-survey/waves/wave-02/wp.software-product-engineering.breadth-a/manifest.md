## 경계 원칙

- 프론트엔드·백엔드라는 직무명은 정규 Unit으로 복제하지 않고 안정된 공학
  행동의 조합 보기로 둡니다.
- API·DB·UI는 특정 제품이 아니라 계약·호환성·무결성·상태 검증을 평가합니다.
- 보안·접근성·운영은 횡단 품질축으로 포함하되 전문 통제 내용은 인접 렌즈가
  소유합니다.
- AI 보조 코딩은 독립 Unit으로 과대승격하지 않고 기존 공학 Unit을 조합하고
  기준선과 비교하는 Set 후보로 둡니다.
- SWEBOK는 누락 방지 기준이며 모든 지식영역을 Candidate 하나씩으로 복제하지
  않습니다.

## 실행 구조

1. Codex 메인 세션이 SWEBOK V4.0a와 관련 공식 사양·문서에서 후보를 발견합니다.
2. 기존 Candidate·Unit·Set·Signal과 인접 렌즈 경계를 대조해 최대 10개로
   정규화합니다.
3. 신규 잠정 subdomain을 Registry에 기록하고 Candidate 정본을 작성합니다.
4. 발견과 분리된 근거·taxonomy·실용성 감사 패스가 전 후보를 검토합니다.
5. Codex 메인 세션이 P0·P1을 반영하고 최종 판정·Checkpoint·검증을 갱신합니다.

## 품질 Gate

- 후보 수는 10개 이하입니다.
- 모든 후보에 두 개 이상의 전이 맥락과 D0·D2 관찰 행동이 있습니다.
- 정의·범위는 공식 사양·공식 문서·1차 연구로 방어합니다.
- 특정 기술 기능을 범용 효과로 일반화하지 않습니다.
- Unit·Set·Resource·Adapter·인접 렌즈 경계를 명시합니다.
- AI 보조 개발 효과는 고정값으로 주장하지 않고 기준선 비교로 제한합니다.
- 근거·taxonomy·실용성 감사 P0 0건, P1 반영 상태여야 승인할 수 있습니다.
- 카탈로그·공개 경계·회귀 테스트와 `git diff --check`가 통과해야 합니다.

## 자동 중단조건

- 필수 근거가 없거나 원문과 핵심 주장이 다릅니다.
- 후보 중복 비율이 15%를 초과합니다.
- 기존 정규 ID 변경·폐기 또는 스키마 변경이 필요합니다.
- 특정 제품 사용법 없이는 관찰 가능한 D2 결과가 성립하지 않습니다.
- 미확인 생산성·품질 효과를 전사 범위로 확정해야만 후보가 성립합니다.
- 스키마·참조·DAG·공개 경계 또는 회귀 검증이 실패합니다.

## 최종 판정

- 후보 10개를 Unit 후보 9개와 Set 후보 1개로 승인했습니다.
- 잠정 subdomain은 업무 Set을 복제하지 않는 9개로 확정했습니다.
- 독립 근거·taxonomy·실용성 감사의 최초 P0는 모두 0건이었고 P1을 반영한
  재감사에서 최종 P0·P1 0건을 확인했습니다.
- AI 보조 변경 Set은 일반 AI 보조 여부의 효과만 비교하며 Agent Harness
  구성요소 효과는 기존 Signal·Probe Set이 소유합니다.
- 후속 사용자 지시에 따라 Unit 후보 9개와 Set 후보 1개를 정규 `cataloged`
  메타데이터로 승격했습니다. 이는 상세 교재·파일럿과 학습효과 검증 완료를
  의미하지 않습니다.
