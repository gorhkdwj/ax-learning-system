# 평가 가설 계약: AI 시스템·에이전트

> 이 문서는 후보 단계의 공통 평가 가설입니다. 정규 Unit 평가나 상세 교재가
> 아니며 사용자 승인과 파일럿 검증 전에는 합격 기준으로 확정하지 않습니다.

## 1. 역할별 목표 깊이

| 대상 | 기본 목표 | 적용 |
|---|---|---|
| 현업 소유자·승인자·검토자 | D0 | 실행 구조·실패·비용·승인 경계를 설명하고 증거를 검토 |
| AI 응용·검색·통합·평가 실무자 | D2 | 소규모 새 과제에 계약을 설계·구현하고 실패 주입으로 검증 |
| 플랫폼·보안·데이터 전문 담당자 | D2 + 역할별 Overlay | 제공된 운영·권한·데이터 정책을 적용하고 전문 D3 설계로 이관 |

모든 구성원에게 에이전트 구현 D2를 요구하지 않습니다. 기업 IAM·분산 플랫폼,
대규모 vector 인프라, 전문 보안시험과 운영 SLO 설계는 이번 패키지의 평가 대상이
아닙니다.

## 2. 공통 fixture 계약

모든 D2 fixture는 시행 전에 다음을 고정합니다.

1. 입력·출력·외부 상태와 업무 완료조건
2. 모델, prompt, corpus, 검색 설정, tool schema와 환경 버전
3. 심은 결함·실패 신호·전체 분모와 심각도
4. 평가자만 보는 숨은 manifest의 필수·금지 source ID, 신뢰 등급, 정답·허용
   상태, 토큰·비용 상한
5. 허용 가능한 대안과 `판단 불가`·중단·인간 이관 조건
6. 반복·시간·token·금액 한도와 소진 뒤 기대 상태
7. 결정적 assertion, 사람 rubric과 필요 시 교정된 model grader의 역할
8. 실제 외부 변경 대신 sandbox 또는 fake adapter를 사용하는 조건
9. 실행 trace, 최종 외부 상태, 인간 개입시간과 작업당 비용
10. release 승인자, 승인 거부·override 사유와 재실행 비용 한도
11. 접근 가능한 동등 입력·응답·오류·승인·복구 방식

확률적 시스템은 단일 실행으로 합격시키지 않습니다. 기본 Gate는 scenario별
독립 실행 10회, 치명 실패 0건, 결정적 assertion 10/10, 전체 업무 성공 80%
이상과 모든 실행의 비용·시간 상한 준수입니다. 성공률이 80~89%이거나 실패 유형이
실행마다 달라 불안정하면 30회로 확대합니다. 자동검사 통과와 업무적으로 올바른
결과도 별도로 기록합니다. 고위험 Overlay는 이 기준을 완화할 수 없고 상향만
할 수 있습니다.

## 3. 공통 fixture 표본

- 문서: 여러 문서 요약, 정책 비교, 구조화 추출과 접근 가능한 보고서 변환
- 리서치: 검색–근거 연결–미확인 기록–문서 갱신·삭제 반영
- 고객지원: 읽기 전용 조회, 답변 초안, 환불·취소 전 승인과 인간 인계
- 운영: 이상 징후 분류, 상태 조회와 가역적 티켓 갱신
- 콘텐츠: 다국어·쉬운 언어·화면낭독 가능한 산출물과 검토
- 지식관리: 문서 추가·개정·삭제 후 검색·인용·메모리 갱신

각 사례군에는 정상과 오류, 답이 있는 경우와 없는 경우, 수용과 거부, 권한 허용과
거절, 성공·부분 성공·취소·시간초과·복구를 포함합니다.

포용성 fixture에는 비영어·저자원·혼합언어, Unicode 이름·주소·날짜·숫자·enum,
낮은 읽기 수준, 키보드·화면낭독기, 음성·영상의 자막·텍스트 대체, 표 구조 보존,
저대역폭·일시적 오프라인 환경을 포함합니다.
모델 응답뿐 아니라 오류·승인·중단·복구 경로도 같은 방식으로 접근 가능해야 합니다.

## 4. 후보별 주요 측정

| 후보 | 주요 측정 |
|---|---|
| LLM 응용 아키텍처·추론 계약 | 실패 반환, 검증되지 않은 외부 변경, 버전 재현성, fallback |
| 시스템 컨텍스트 | 필수 근거 회수, 오염 지시 수용, 위치별 성공, 토큰 예산 |
| 검색·근거 연결 생성 | retrieval 품질, 보류 적중, source ID, 검색·생성 실패 귀속 |
| 구조화 출력 | 스키마 위반 탐지, 유효하지 않은 결과 전파, repair 후 의미 오류 |
| AI 도구·함수 계약 | 도구 선택·인자·오류 전달, 중복 부작용, 최종 상태 |
| 상태·메모리·인계 | 재개, stale·충돌 기억, 삭제, 소유권·artifact, 중복 실행 |
| workflow·agent 토폴로지 | 방식별 성공·지연·비용·복구·인간 개입과 최소 복잡도 |
| 시스템 평가·회귀 | 치명 실패·holdout 회귀, grader-사람 합치, 반복 분산 |

## 5. 실패 주입과 치명 조건

다음 실패를 후보 범위에 맞게 주입합니다.

- 모델·프롬프트·설정 변경과 schema 미지원
- 필수 context 누락, 상충 지시, stale 자료와 간접 prompt injection
- 검색 누락·잘못된 재정렬·삭제되지 않은 문서·권한 밖 원문
- refusal·잘림·누락·추가 필드와 의미상 잘못된 구조화 결과
- 잘못된 tool 선택·인자, timeout, 부분 결과, 중복 호출과 stale 결과
- checkpoint 유실, 오래되거나 출처 없는 memory, 취소·인계 누락
- 무한 반복, 비용·시간 한도 초과, 승인 거절과 잘못된 완료
- 평가 누출, grader 편향, 숨은 holdout 실패와 단절된 trace

치명 조건은 권한 없는 외부 변경, 민감정보 노출, 금지된 상태 변경, 무승인 고위험
행동, 삭제·취소 무시, 실패를 성공으로 보고하는 것입니다. 평균 점수로 상쇄하지
않습니다.

## 6. 확정 경계와 파일럿 추적

- 동일 계약 테스트를 통과하는 Adapter 2개를 요구하며 하나는 반드시 로컬 fake
  adapter, 다른 하나는 실제 공급자 또는 독립 참조 구현으로 둡니다. 특정 공급자
  기능의 동등성은 가정하지 않습니다.
- RAG Set은 기존 `unit.ai.grounded-output-evaluation@1.0.0`을 필수 선행으로
  재사용합니다. 시스템 평가·회귀 Unit에서는 grounding을 측정할 때만 권장
  선행으로 사용합니다.
- 도구 계약 코어는 목적·입출력 schema·오류 의미·부작용 등급·권한·멱등성
  요구·상관관계입니다. handoff 코어는 ID·소유자·상태·payload·artifact·
  완료·취소·실패·provenance·만료입니다. 프로토콜 전송·인증·discovery·
  streaming·version negotiation과 SDK 세부는 Adapter·Resource입니다.
- 상태·메모리·handoff는 중단·재개·위임 뒤 과업 소유권과 상태를 보존하는 하나의
  에이전트 연속성 계약 Unit으로 평가합니다.
- 자동 grader는 사람 기준에 교정하며 단독 최종판정자로 사용하지 않습니다.
- 다중 agent는 기본값이 아니며 단일 agent 또는 고정 workflow 대비 순효과를
  기존 Signal의 Probe Set에서 검증합니다.
- memory의 개인정보 보존·삭제와 tool의 권한정책은 전문 보안·법무 Overlay가
  필요합니다.
- 운영 telemetry·SLO·incident와 배포 변경은 플랫폼·운영 렌즈가 소유합니다.
