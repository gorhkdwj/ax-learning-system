## 기존 정본과 예상 경계

- `unit.ai.grounded-output-evaluation@1.0.0`은 제공 근거와 AI 출력의 연결 평가를
  이미 소유하므로 신규 후보와 중복 여부를 우선 검사합니다.
- `signal.agent.agent-harness@1.0.0`은 `substantiated` 상태이며 독립 Unit보다
  여러 기반 역량을 조합한 Probe Set 목적지가 제안되어 있습니다.
- `signal.agent.agent-control-loop@1.0.0`은 `researching` 상태이므로
  `Loop Engineering` 명칭을 안정된 Unit으로 자동 승격하지 않습니다.
- `Agent Harness`와 실행 제어 루프는 새 Candidate·node로 복제하지 않고 기존
  Signal의 Probe Set·관찰 경로를 유지합니다.
- Wave 1의 해법 적합성·과업 배분·인간-AI 통제와 Wave 2 첫 패키지의 신뢰·검증
  후보를 기술 구현 범위와 분리합니다.

## 실행 구조

1. 읽기 전용 조사자가 공식 사양·공식 문서·1차 연구에서 후보와 근거를 조사합니다.
2. 별도 읽기 전용 경계 감사자가 기존 Unit·Signal·인접 렌즈 중복을 레드팀합니다.
3. Codex 메인 세션이 후보를 최대 10개로 정규화하고 필요한 잠정 node만 기록합니다.
4. 발견자와 분리된 감사자가 근거·taxonomy·실용성을 독립 감사합니다.
5. Codex 메인 세션이 P0·P1을 반영하고 Checkpoint와 자동검증을 갱신합니다.

## 품질 Gate

- 후보 수는 10개 이하입니다.
- 모든 표시명은 한국어를 기본으로 하고 영문은 canonical name·node·병기로 둡니다.
- 각 후보는 시스템 수준의 관찰 가능한 D0~D2 행동과 깊이 상한을 가집니다.
- 공식·표준·1차 근거를 우선하고 공급자 문서는 일반화 제한을 기록합니다.
- RAG·컨텍스트·도구·메모리·에이전트·평가의 경계를 명시합니다.
- 기존 Unit·Signal 및 다른 Wave 2·3 렌즈와 중복을 전수 확인합니다.
- 신흥 명칭은 안정된 기반 능력과 분리하고 필요하면 기존 Signal로 라우팅합니다.
- 독립 근거·taxonomy·실용성 감사 후 P0 0건, P1 반영 상태여야 합니다.
- 카탈로그·공개 경계·회귀 테스트와 `git diff --check`가 통과해야 합니다.

## 자동 중단조건

- 필수 근거가 없거나 원문과 핵심 주장이 다릅니다.
- 후보 중복 비율이 15%를 초과합니다.
- 새로운 독립 대분류, 기존 ID 변경·폐기 또는 스키마 변경이 필요합니다.
- 정규 Unit·Set·Signal 승격 없이는 진행할 수 없습니다.
- 특정 공급자 기능을 범용 표준으로 일반화해야만 후보가 성립합니다.
- 스키마·참조·DAG·공개 경계 또는 회귀 검증이 실패합니다.
