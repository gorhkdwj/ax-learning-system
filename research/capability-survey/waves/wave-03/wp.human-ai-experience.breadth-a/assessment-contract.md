# 평가 계약: wp.human-ai-experience.breadth-a

## 공통 원칙

- 평가는 공개·합성 입력, local prototype과 봉인된 사용자·오류 fixture만
  사용합니다.
- 실제 개인정보·계정·자격증명·결제·삭제·고위험 외부 변경은 사용하지 않습니다.
- AI 제안·설명·개인화의 유창성이나 만족도를 과업성공·이해·통제·복구의
  대리 지표로 사용하지 않습니다.
- 각 D2 후보는 정상 상태뿐 아니라 오류·거부·무응답·지연·변경·접근성
  시나리오를 포함합니다.
- 사용자 평가는 표본·과업·맥락 안의 formative evidence이며 보편적 효과나
  규제 적합성을 확정하지 않습니다.

## D0 공통 Gate

- AI의 실제 역량과 사용자 mental model을 구분합니다.
- 설명 가능성, 유용한 사용자 설명과 법적 설명 의무를 구분합니다.
- 피드백 수집, 결과 수정, 개인화·기억과 모델 학습을 구분합니다.
- 형식적 승인과 실질적인 판단·통제를 구분합니다.
- 대화 유창성, 의도 이해와 실제 과업 완료를 구분합니다.
- 일반 UI 접근성과 AI의 생성·변동·다중양식 요구를 구분합니다.
- 사회적 단서와 실제 역량·의도·감정·책임을 구분합니다.

## D2 공통 Gate

- prototype과 정답 manifest, 실패 주입 목록, 관찰 protocol을 실행 전에
  고정합니다.
- 지원·미지원 과업, 인간 역할, 한계와 도움 경로의 이해 오류를 기록합니다.
- 설명은 사용자 질문에 답하며 근거 없는 인과표현과 필수 질문 누락이 없습니다.
- 수정·거부·undo·reset은 UI 표시와 실제 fixture 상태가 일치합니다.
- 승인·거부·override·이관에서 무승인 실행과 결정기록 누락이 없습니다.
- 대화 repair는 제한 단계 안에 완료·수정·재개·fallback 중 하나로 끝납니다.
- memory fixture는 stale·충돌·삭제실패·문맥전환에서 비의도 노출과 거짓
  완료가 없습니다.
- 경험 평가는 과업성공·mental model·의존·통제·복구·접근성을 함께 관찰하고
  치명 실패 누락이 없습니다.

## 중단조건

- 실제 개인정보·자격증명·운영 계정이 필요합니다.
- companion·미성년자·정신건강·치료 맥락을 일반 UX 실습으로 평가해야 합니다.
- 사용자 동의·철회·보유정책이나 고위험 승인권을 임의로 정해야 합니다.
- 설명·의인화·개인화가 특정 효과를 보편적으로 낸다고 가정해야 합니다.
- 접근성 Draft를 정식 표준 준수 근거로 표현해야 합니다.
- prototype 밖 실제 외부 상태를 변경하거나 원본 파일을 덮어써야 합니다.
