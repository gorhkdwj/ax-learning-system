# AX 커리큘럼 기반 구축 계획

## 목표

전사 AX 역량 전체를 탐색할 수 있으면서도 현재 업무가치에 따라 학습을 동적으로
우선 배정하고, 정확하고 재사용 가능한 학습자료를 지속적으로 확장할 기반을 구축합니다.

## 계획 원칙

- 전체 역량 범위 조사와 상세 교재 제작을 분리합니다.
- 메타데이터와 검증 구조를 콘텐츠 대량 제작보다 먼저 확립합니다.
- 카탈로그는 넓게 조사하되 상세화는 우선순위에 따라 지연합니다.
- 첫 파일럿으로 구조를 검증한 뒤 전체 범위를 확장합니다.
- 각 단계는 검증 가능한 산출물과 완료조건을 가집니다.

## Phase 0. 거버넌스 등록

### 산출물

- 루트 `AGENTS.md`
- 상세 학습 거버넌스
- 4층 학습 시스템 아키텍처
- Unit, Learning Set, Resource JSON Schema 초안
- 본 실행계획

### 완료조건

- 합의된 원칙이 문서 간 충돌 없이 반영됩니다.
- 모든 JSON Schema가 유효한 JSON으로 파싱됩니다.
- 절대 작업경로가 학습자료 지침에 포함되지 않습니다.

## Phase 1. 메타데이터 기반

상태: 2026-07-26 완료

### 작업

1. Unit, Set, Resource JSON Schema를 실제 예제 메타데이터로 검증합니다.
2. Unit, Set, Resource 작성 템플릿을 만듭니다.
3. 중복 ID, 상대경로, 참조 누락과 필수 필드를 검사하는 검증기를 만듭니다.
4. 선행관계 DAG와 버전 제약 검사를 추가합니다.
5. 메타데이터 변경 절차와 오류 메시지 형식을 정합니다.

### 산출물

- 최소 예제 Unit 2개
- 최소 예제 Learning Set 1개
- Unit별 Resource 예제
- 단일 검증 명령

### 완료조건

- 깨끗한 환경에서 예제가 스키마 검증을 통과합니다.
- 의도적으로 잘못된 ID, 절대경로, 누락 참조와 순환관계를 탐지합니다.

## Phase 1A. Trend Signal 연구 인입

상태: 2026-07-26 완료

### 작업

1. 신흥 용어·개념·패턴을 Unit에 바로 넣지 않는 연구 인입 스키마를 만듭니다.
2. 정의와 효과 신뢰도, claim–evidence, 별칭·중의성, 목적지와 검토 주기를 분리합니다.
3. 상태 전이, 정확한 버전 참조, 명칭 충돌, 계층 순환과 승격 조건을 검증합니다.
4. Harness Engineering, Loop Engineering, Karpathy-style LLM Wiki를 최초 사례로 조사합니다.

### 완료조건

- 세 사례가 같은 스키마와 단일 카탈로그 검증 명령을 통과합니다.
- 정의가 안정된 사례와 아직 용어 경계가 불안정한 사례를 다른 상태로 표현합니다.
- 검증 전 Signal이 Learning Unit이나 사용자 학습 경로로 직접 편입되지 않습니다.
- 정의가 확인되어도 효과가 불확실하면 비교 Probe로 분리할 수 있습니다.

## 횡단 기반. Public·Private 저장 경계

상태: 2026-07-27 완료

### 작업

1. 공개 학습 시스템과 개인 Vault를 별도 저장소 경계로 분리합니다.
2. 원문·개인 기록·임베딩·비공개 생성물을 Vault로 이관합니다.
3. 공개 시스템은 Vault 없이도 작동하고, 선택적 Vault 경로는 단일 해석기를
   통해 주입합니다.
4. 공개 경계, 대용량 파일, 카탈로그와 테스트를 단일 검증 명령으로 확인합니다.

### 완료조건

- 공개 저장소에 원문·개인 기록·임베딩과 대용량 비공개 파일이 없습니다.
- 기존 정규 상대경로와 카탈로그 참조가 이동 후에도 유효합니다.
- Vault가 존재하는 실행과 존재하지 않는 실행이 모두 검증을 통과합니다.
- 공개 HTML에 원문 전문이나 임베딩을 삽입하지 않는 경계가 문서화됩니다.

## Phase 2. 전사 AX 역량지도 조사

상태: 2026-08-02 Wave 1~3 조사·승격과 Wave 4 교차 Coverage 검토 완료,
Wave 5 정규화 계획 준비

### 조사 범위

- AX 전략·업무 프로세스·제품
- AI 리터러시·LLM·RAG·에이전트
- 프론트엔드·백엔드·DB·소프트웨어 공학
- 데이터 수집·분석·품질·거버넌스
- API·MCP·SaaS·업무자동화
- UI·UX·Human-AI Interaction
- 테스트·평가·관측성·배포·운영·비용
- 보안·개인정보·권한·감사·법무·윤리
- 조직 변화·협업·성과측정

### 조사 방법

1. 분야별 읽기 전용 서브에이전트가 독립적으로 공식·1차 출처를 조사합니다.
2. 메인 세션이 후보를 Capability Candidate 스키마로 staging합니다.
3. 출처·taxonomy·실무성 감사 에이전트가 발견자와 독립적으로 교차 검토합니다.
4. 조사 중 발견한 신흥·중의적 개념은 Trend Signal로 먼저 수집하고 검증합니다.
5. 후보 역량과 Unit을 통합하고 중복·누락을 교차 검토합니다.
6. 조사 렌즈와 잠정·정규 분류는 Taxonomy Registry에서 분리하고 Candidate·Unit은
   활성 node를 참조합니다.
7. 역할·업무·파이프라인 보기는 정규 분류를 복제하지 않고 node 조합으로 만듭니다.
8. 항목마다 유형, 범위, 관계, 공식 출처와 카탈로그 상태만 먼저 기록합니다.
9. 상세 자료가 필요한 항목과 메타데이터만 유지할 항목을 분리합니다.

세부 Wave, 작업 패키지 상한, 표본감사와 중단조건은
`docs/research/phase2-capability-survey-runbook.md`를 따릅니다.

### 완료조건

- 모든 대분류에 최소 하나 이상의 공식 또는 1차 출처가 연결됩니다.
- 후보 Unit마다 등록·보류·제외 사유가 기록됩니다.
- 범위가 특정 직무나 현재 업무에만 한정되지 않았음을 검토합니다.
- 모든 Candidate에 라우팅 제안과 이유가 있으며, 고위험·D3·D4·논쟁 후보는
  독립 전수감사를 통과합니다.
- 일반 후보의 층화표본 감사에서 중대한 출처·분류 오류가 없습니다.
- 분류 Registry의 node·보기·외부 참고체계와 Candidate·Unit 참조 검증이
  통과합니다.

## Phase 3. 우선순위와 비즈니스 임팩트

### 작업

1. 사용자의 현재 역량, 반복 업무, 시간·도구·비용 제약을 진단합니다.
2. 후보 Learning Set의 직접 가치, 위험 감소, 선행효과, 재사용성,
   전략적 옵션가치와 근거 신뢰도를 평가합니다.
3. 필수·선택, 실행 우선순위와 선행관계를 별도로 지정합니다.
4. 불확실한 항목은 전체 과정 대신 시간 제한형 Probe로 배정합니다.

### 완료조건

- 각 활성 후보 Set에 현재 기준선, 기대 결과, 성공·중단 조건이 있습니다.
- 현재 학습 배정에 비즈니스 임팩트 또는 필수 통제 근거가 있습니다.
- 점수가 낮더라도 필수 안전통제가 누락되지 않습니다.

## Phase 4. HUB 최소 기능

전사 지도와 Learning Set 후보 구조가 검증된 직후 최소 HUB를 구축합니다.
첫 파일럿 전에는 고급 추천, 로그인, 서버·DB 기반 진행률 분석을 추가하지 않습니다.

### 우선 기능

- Unit과 Set 검색·필터
- 전사 역량지도와 선수지식 DAG
- 현재 추천 학습 경로와 진행 상태
- 필수·선택, 지금·다음·이후 보기
- 버전·출처·검증·갱신 필요 상태
- 예상 시간·비용과 비즈니스 임팩트

### 완료조건

- HUB가 정규 메타데이터에서 자동 생성됩니다.
- 생성 결과를 직접 수정하지 않고 원본 변경이 반영됩니다.
- 깨진 참조와 오래된 자료가 사용자에게 보입니다.
- 키보드로 주요 기능을 사용할 수 있고 핵심 정보의 텍스트 대체본이 있습니다.

## Phase 5. 첫 파일럿 Learning Set

### 선정 기준

- 현재 업무에 실제 적용할 수 있습니다.
- 여러 Unit을 조합하여 4층 구조와 참조 방식을 검증할 수 있습니다.
- 안전한 합성 데이터 또는 샌드박스에서 실습할 수 있습니다.
- 자동검증과 실제 결과 상태 확인이 가능합니다.
- 범위가 작아 짧은 피드백 주기를 만들 수 있습니다.

### 구축 순서

1. 업무 현황, 병목, 입력·출력과 KPI를 정의합니다.
2. 에이전트, 결정적 자동화와 기존 SaaS 중 적합한 방식을 비교합니다.
3. 필요한 Unit과 목표 D 수준을 정합니다.
4. 정규 Unit Resource와 얇은 업무 Overlay를 작성합니다.
5. 정상·오류·권한·공격 입력을 포함한 평가 하네스를 만듭니다.
6. 통합 산출물, 승인 지점, 중단·롤백 조건을 검증합니다.

### 완료조건

- Set이 공통 Unit 콘텐츠를 복제하지 않습니다.
- 단계별 산출물과 검증 게이트가 모두 실행됩니다.
- 인간 검토시간을 포함한 업무효과를 기준선과 비교할 수 있습니다.
- 다른 업무 맥락으로의 전이과제가 존재합니다.

## Phase 6. 확장과 운영

### 작업

- 우선순위가 높은 Set과 공통 Unit부터 점진적으로 확장합니다.
- 실제 학습 및 업무 적용 결과를 메타데이터와 평가에 반영합니다.
- 공식 문서 변경, EOL, 실행 검증 만료를 감시합니다.
- 정오표, 대체 기술, 폐기 항목과 차이 학습을 관리합니다.
- 중복 콘텐츠와 과도한 유지비용을 정기적으로 정리합니다.

### 운영 지표

- 실제 과제 성공률과 첫 시도 성공률
- 인간 검토시간과 재작업률
- 오류·운영 유출결함·자동복구율
- 업무당 비용과 처리시간
- 사용 빈도와 다른 업무로의 전이
- 갱신이 필요한 자료와 지원 종료 참조 수

## 다음 실행 순서

Phase 0, Phase 1과 Trend Signal 연구 인입 기반을 완료했고, Phase 2의 Wave 1~3
Breadth 조사·승격과 Wave 4 교차 Coverage 검토를 완료했습니다. 다음은 Wave 5에서
후보 명칭·중복·상하위 경계, stable core와 Adapter·Resource·Set 목적지 및
provisional taxonomy·역할 view를 정규화하는 것입니다. 기존 ID 변경과 canonical
분류 확정은 영향분석과 사용자 승인 뒤 수행합니다. 상세 교재는 Phase 3 우선순위
평가 전까지 대량 생성하지 않습니다.
